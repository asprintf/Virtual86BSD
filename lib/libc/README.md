# libc — a POSIX.1-2024 C library for x86-64 Linux

A from-scratch C library implementing ISO C17 and POSIX.1-2024
(SUSv5, XSI option), meant to replace glibc or musl on x86-64 Linux.
It talks to the kernel directly through system calls and is built with
either gcc or the project's own `c17` compiler.

Work proceeds header by header; see `STATUS.md` for where things stand.

## Building

The makefile is a POSIX makefile; the collection's own make, c17 and ar
build the library without any other tool:

    make                     # with gcc: build/gcc/lib/{libc.a,crt1.o,crti.o,crtn.o},
                             #   libc.so (also the dynamic linker), Scrt1.o, rcrt1.o
    make CCNAME=c17          # with c17 (on PATH), which also assembles the .s files
                             #   and links libc.so (c17 -G)
    make check               # namespace check, header checks, tests
    make CCNAME=c17 check
    make sysroot             # build/<cc>/sysroot (include/, lib/), for C17_LIBC=
    make install PREFIX=/usr DESTDIR=dir    # headers and libraries into dir/usr

Compiler settings are in `config/gcc.mk` and `config/c17.mk`.  POSIX
make has no wildcards or pattern rules, so `rules.mk` lists every object
with its rule; it is generated by `tools/genmk.sh` (run it after adding
or removing a source file; `make check` notices when it is stale).

Using it:

    tools/libc-cc gcc -O2 -o prog prog.c
    tools/libc-cc c17 -o prog prog.c        # = C17_LIBC=<sysroot> c17 ...

`tools/libc-cc` swaps the system headers and start files for this
library's.  Executables are static unless `LIBC_LINK` says otherwise:

    LIBC_LINK=dynamic tools/libc-cc gcc -o prog prog.c     # a PIE using libc.so
    LIBC_LINK=dynamic tools/libc-cc c17 -o prog prog.c     # (c17: not position-independent)
    LIBC_LINK=static-pie tools/libc-cc gcc -o prog prog.c
    tools/libc-cc gcc -shared -fPIC -o libx.so x.c          # a shared object
    tools/libc-cc c17 -G -o libx.so x.c                     # (c17)

`libc.so` is its own program interpreter (PT_INTERP names it), and run
as a command it runs a program: `build/gcc/lib/libc.so prog args`.
Only gcc builds it: c17 makes neither shared objects nor
position-independent code, but c17's dynamically linked programs use it.  The mathematics library is part of
`libc.a`; `-lm` (also `-lrt`, `-lpthread`, `-lxnet`, `-ldl`, `-lcrypt`) finds an empty archive.  `LIBC_LIB=dir` links with a library
built by the other compiler.  With c17 nothing else is needed:
`C17_LIBC=dir` points c17 at `dir/include` and `dir/lib`.

The POSIX utility collection builds on this library with either compiler
(its `run_tests.sh` rebuilds every utility with the `CC` given):

    CC="/path/to/libc/tools/libc-cc gcc" sh run_tests.sh
    CC="/path/to/libc/tools/libc-cc c17" sh run_tests.sh   # c17 on PATH, C17_LIBDIR set

c17 itself, built that way, is self-hosting on this library (see
`STATUS.md`, stage 10).

## Design

**Kernel interface.**  System calls go through `src/internal/syscall.h`.
With gcc they are inline `syscall` instructions; with a compiler without
inline assembly (c17) they go through one assembly routine,
`__syscall6` in `src/arch/x86_64/syscall.s`.  The same split is used for
atomics (`src/internal/atomic.h` / `atomic.s`) and for reading the thread
pointer.  Everything compiler-specific is confined to those three places,
so the C sources are plain C17.

**Start-up.**  `_start` (crt1.s) hands the initial stack to
`__libc_start_main`, which finds the auxiliary vector, sets up static TLS
and the thread pointer, seeds the stack-protector canary from
`AT_RANDOM`, runs `.preinit_array`, `_init`, `.init_array`, then calls
`exit(main(...))`.

**Threads from day one.**  `%fs` always points at a `struct __pthread`
(TLS variant II), also in single-threaded programs: `errno` lives there,
`_Thread_local` works, and the canary is at `%fs:0x28` where gcc expects
it.  Internal state is protected by futex locks (`src/internal/lock.c`),
so stdio, malloc etc. are thread-safe as they are written.  Threads
are `clone()`d with stack, TSD and TLS in one mapping (`src/thread/`).

**Headers.**  Feature-test macros are resolved once, in
`include/bits/features.h`, into `__POSIX_VISIBLE` / `__XSI_VISIBLE` /
`__C11_VISIBLE`.  With no feature-test macro everything is visible;
under a strict ISO mode (`gcc -std=c17`) only ISO C is.  Shared types
are defined in exactly one place, `include/bits/alltypes.h`, requested
with `__NEED_<type>` macros.  The compiler supplies `<stddef.h>`,
`<stdarg.h>`, `<float.h>` and `<stdatomic.h>` (both gcc and c17 ship
them); the library supplies the rest.

**Namespace.**  A strictly conforming ISO C program may define any name
ISO C does not reserve, e.g. its own `strdup` or `environ`.  So no object
file defining an ISO C function may define or (transitively) reference a
POSIX name: internal calls use `__`-prefixed names, and ISO and POSIX
functions live in separate files.  POSIX data aliases such as `environ`
are weak.  `tools/check-namespace.sh` enforces this on every `make check`.
No GNU attributes (weak aliases, visibility) are used in C, since c17
does not implement them; where an alias is needed it is made in assembly.

**Close-on-fork.**  POSIX.1-2024's `O_CLOFORK`/`FD_CLOFORK` go to the
kernel when it has them (V86BSD's kernel; found out once, by whether
`F_GETFD` reports `FD_CLOFORK` on a descriptor opened with `O_CLOFORK`).
Linux has no equivalent, so there the library keeps a bitmap of flagged
descriptors (`src/internal/clofork.c`) and `fork()` closes them in the
child.  Only the library sets flags, and `close()`/`dup2()`/`dup3()`
clear the descriptor they free or replace, so reused descriptor numbers
start clear.

**Cancellation points** go through `__syscall_cp*` macros and one
assembly routine whose address range the `SIGCANCEL` handler checks, so
a cancellation request is neither lost nor acted on after the system
call took effect.

**Locales.**  The POSIX locale, a built-in C.UTF-8, and locale
directories in glibc's binary format (what `localedef` writes), with UTF-8,
single-byte codesets or EUC-JP, SHIFT_JIS, EUC-KR, GB2312, GBK, GB18030 and
BIG5; collation by the locale's LC_COLLATE, as glibc (`strcoll` with
glibc's own algorithm, bracket ranges by the collation sequence).

**Mathematics.**  Computed in the x87 80-bit format and rounded once to
float or double, so those results are almost always correctly rounded;
the x87 instructions are reached through `src/arch/x86_64/x87.s` (c17 has
no inline assembly) and the argument reductions are exact. `<fenv.h>`
keeps the x87 unit and SSE in step. Details in `STATUS.md`.

**malloc.**  Boundary-tag chunks with immediate coalescing and 64
segregated bins in mmap'd regions; requests of 256 KiB and up get their
own mapping.  One global lock for now.

**Dynamic linking.**  `libc.so` is the library and the dynamic linker
(`src/ldso/dyn/dynlink.c`, as in musl): it relocates itself, loads the
program's `DT_NEEDED` objects (libc.so, libm.so, libpthread.so ... are
itself), lays out the static TLS of all of them, binds everything at
once, and runs the constructors in dependency order from
`__libc_start_main`.  `dlopen` with `RTLD_LOCAL`/`RTLD_GLOBAL`, dynamic TLS
for dlopen'ed objects (`__tls_get_addr`), `RTLD_DEFAULT`/`RTLD_NEXT`,
`dladdr`, ``, `DT_RUNPATH`, `LD_LIBRARY_PATH`, `LD_PRELOAD`, and
`r_debug` for debuggers.  Calls inside libc.so bind to it
(`-Bsymbolic-functions`); data goes through the GOT, so a program's copy
relocations work.  `dlclose` does not unload (POSIX allows it).

## Testing

All test tooling is POSIX sh and awk; the only other requirement is a C
compiler.

* `tests/t_*.c`: differential. Each is built against the system C library
  (gcc, glibc) and against this one; the outputs must be identical. They
  cover randomised string functions, the `strerror` and `strsignal`
  messages, all of `<ctype.h>`, the `strtol`
  family, `qsort`/`bsearch`, `getopt`, `localtime`/`mktime`/`strftime` across
  many time zones, `strptime`, `printf` (hundreds of thousands of random
  floating-point conversions), `strtod`/`scanf`, `random`, the `rand48`
  family, `a64l`/`l64a`, the multibyte functions, the user and group
  databases, `scandir`, whole matches of 20 000 random regular
  expressions (and glibc's `\<`, `\b`, `\w` extensions), `fnmatch` (30 000 random cases), `glob` and
  `basename`/`dirname`, and locales: `t_locale` compares, in C, C.UTF-8
  and locales that `run.sh` makes with the `localedef` it finds (glibc's
  or the suite's), langinfo, localeconv, every code point's classes, case
  maps, width and multibyte form, locale-dependent printf/strtod/
  strftime/strptime/strfmon, wide strings, regex and fnmatch in UTF-8,
  and iconv for 22 codesets over all of the BMP and beyond; `t_collate`:
  strcoll/strxfrm/wcscoll/wcsxfrm, orders and `[=x=]` in regex and
  fnmatch, in those locales and in xx_XX, made from `tests/collate.def`
  (a contraction, expansions, ignored characters, a backward and a
  position level); `t_mbcs`: the multibyte codesets (every byte and pair
  of bytes, every code point, strings in printf, regex, fnmatch, wide
  streams); `t_wide`: swprintf and the wide scanf in all those locales; and
  `t_inet`: address conversions (20 000 random IPv6 addresses),
  getaddrinfo/getnameinfo in some 250 combinations of names, services,
  families and flags, and the network databases; `t_search` (`hsearch`,
  the `tsearch` family, `lsearch`, `insque`), `t_fmtmsg` (`MSGVERB`
  settings, labels, severities) and `t_crypt` (all five `crypt` schemes,
  against libxcrypt: a test names extra libraries of its reference build
  in a `REFLIBS:` comment).
* `tests/u_*.c`: differential within a tolerance, for the mathematics:
  built against both libraries, the system's build writes its results
  and this one's reads and compares them, in units in the last place.
  `u_math` covers every `<math.h>` function in three precisions (special
  values with `errno`, and random arguments over each domain), `u_complex`
  every `<complex.h>` function; both print the largest error per function.
* `tests/s_*.c`: self-checking.
  * `<aio.h>` (both notifications, `aio_suspend` timeouts and interruption, cancelling blocked pipe reads, `lio_listio`, ordering of appends, fork) and `posix_devctl`; `<ndbm.h>` (20 000 records, big pairs, deletion, iteration, read-only), the balance of the `tsearch` tree, `<dlfcn.h>` on the program's own symbols, `encrypt`/`setkey` against the FIPS 81 vectors.
  * Networking and IPC: Unix-domain, TCP and UDP sockets, descriptor passing with the close-on-exec/close-on-fork flags, cancellation in `accept`; the DNS resolver against the test's own DNS server; XSI message queues, semaphores and shared memory across processes; POSIX message queues with both kinds of notification; syslog read back from a `/dev/log` of the test's own.
  * Threads: every `<pthread.h>`, `<semaphore.h>`, `<sched.h>` and `<threads.h>` facility, cancellation in all its forms, robust mutexes whose owner thread or process dies, fork and set*id with threads, `SIGEV_THREAD` timers, stdio/malloc/locales under threads.
  * Mathematics: Bessel functions against exact values (from bc), the floating-point environment and rounding modes, `fma` in every mode, the classification macros, `<tgmath.h>` type selection.
  * malloc stress: 300k random operations, alignment, overflow.
  * Start-up, TLS, `atexit`, error strings.
  * Files: open/at-functions, stat, links, modes, times, `fcntl`, the dup family, close-on-fork across `fork()`, `statvfs`/`pathconf`.
  * Time: clocks, timers, `nanosleep`, TZ strings, `getdate`.
  * stdio: buffering modes, `ungetc`, seeking, `fmemopen`, `open_memstream`, `popen`, `freopen`, `tmpfile`, locking, exit flushing.
  * stdlib: `realpath` (symlinks, loops, dangling links), `mkstemp`/`mkostemp`/`mkdtemp`, `system`, `getsubopt`, pseudo-terminals.
  * Directories (`readdir`, `telldir`/`seekdir`, `posix_getdents`), the user accounting database (when it can be created), `getlogin`.
  * Locales: setlocale names, locale objects, `uselocale`, the `_l` forms, catalogs and message objects (made by the test), plurals, codeset conversion, wide streams, `open_wmemstream`, `wcsftime`, `swprintf`, UTF-16.
  * Regular expressions: the POSIX rules for subexpressions, minimal repetition, back-references, `REG_STARTEND`, long subjects; multi-character collating elements (`[.ch.]`, `[=ch=]`) in regcomp and fnmatch, in xx_XX (`s_collsym`).
  * `setjmp`/`sigsetjmp`, `posix_spawn` with file actions and attributes, `wordexp`, `nftw`, `fnmatch` with case folding.
  * Processes and signals: fork/exec/wait, `sigaction` with `SA_SIGINFO`, masks, `sigqueue`, `sigwaitinfo`/`sigtimedwait`, `alarm`/`pause`, `sig2str` round trips, `sysconf`/`confstr`, poll/select, mmap, `shm_open`.
* The same tests run linked dynamically (`LIBC_LINK=dynamic sh run.sh gcc`,
  also with c17) and as static PIEs; `s_dlopen` then dlopens the objects
  `run.sh` builds from `tests/dl/`.
* `tests/headers.sh`: every header compiles alone, twice (include guards). gcc tries seven language modes, c17 four feature-macro settings. Under strict ISO C, POSIX names must stay hidden.
* `tools/check-namespace.sh`: the namespace rule above.

`tests/run.sh gcc` and `tests/run.sh c17` run the programs. The four
combinations (library built by either compiler, programs by either) all
pass.

## Layout

    include/             public headers (bits/ = internal helpers)
    config/              per-compiler make settings
    rules.mk             generated make rules (tools/genmk.sh)
    src/arch/x86_64/     start files, syscall/atomic/TLS glue, memcpy/memset
    src/internal/        library-private headers and helpers (syscalls, locks,
                         atomics, close-on-fork emulation)
    src/<area>/          implementation, one directory per area
    tests/               test programs and scripts
    tools/               libc-cc driver wrapper, namespace checker, genmk.sh;
                         maintainer tools that made generated tables:
                         mkuctype.c (Unicode data of C.UTF-8), mkcharsets.c
                         (single-byte codesets), mkcjk.c (CJK codesets);
                         bc scripts: mktwoopi.sh (bits of 2/pi), mkzeta.sh
                         (zeta values for lgamma), mkbessel.sh (test values),
                         mkhash.sh (MD5 and SHA-2 constants)
